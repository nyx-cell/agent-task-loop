# Product

## Platform

web

## Users

一个人，在自己的电脑上，同时使唤好几个本地编码 agent。装了哪几位由使用者的机器决定，不由产品决定。
典型场景是深夜独自工作：开一间房，把问题说一遍，让在场的 agent 依次接话，看谁说得对、谁被挡住了、谁没跑起来，然后接着说。
使用者是开发者，懂 CLI 和 git，但不想在界面里读到系统内部的词。

## Product Purpose

Rivus room-web 是本地多 agent 的聊天室。一句话发给房间，在场成员按既定顺序逐个回复，所有人读写同一条对话流。
它存在的理由是把「多个 CLI 各自开一个终端来回粘贴」变成一条时间线。
成功的样子：使用者随时知道现在轮到谁、后面还有谁、这一位已经等了多久、谁的回复被挡住了或失败了，并且永远能继续往下说。

## Positioning

顺序发言是产品机制，不是限制：每个 agent 回复前必须读到它上次没读过的所有消息，读到一半有人插话就先「挡住」（HELD），重读后再答。
邻近产品把多个模型并排放，各答各的；这里所有人在同一条流里接话，后说的人看得见先说的人。

## Operating Context

- 全部本地：服务只绑 127.0.0.1，房间存在本机 sqlite，agent 通过本机已登录的 CLI 调用。没有账号、没有云端。
- 一轮回复常常要 30 到 120 秒，五位成员依次说完可能几分钟。使用者在等待里最需要的是「谁在说、说了多久、后面还有谁」。
- 消息可以 @ 单独一位；不 @ 则所有在场成员按成员顺序依次回复。发言中途再发消息会排到这一轮后面，不会被拒绝。
- 成员顺序可以调整，也是「检查连接」时的报数顺序。
- 智能体页面维护每位 agent 的常驻系统提示，所有房间共用，存在本机。
- 每位 agent 是 rooms.sqlite 里 agents 表的一行：id、显示名、角色词、一条 shell 命令、建行时随机分到并存下的身份色、以及这一位的系统提示。产品不区分「内建」和「自定义」，代码里也没有任何一位 agent 的名字。
- 行为指令属于 agent 自己：房间的提示词只给房间事实（你是谁、这间房有几位、说过什么），「要具体简洁」「先读完再答」这类要求写在各自的系统提示里，可以逐位改。改完下一轮生效，不用重启。

## Capabilities and Constraints

- 已有动作：发消息、@ 提及（含自动补全）、管理成员（增删排序）、检查连接（按顺序报数验证每个 CLI 能读写对话）、读取更新并重答（HELD 草稿重试，最多 3 次追平）、清空对话（保留房间）、新建房间、切换房间。
- 添加一位 agent 现阶段靠手写 INSERT（见 README），界面上还没有；智能体页的「重新扫描」会重读 agents 表并重新探测每条命令。
- 没有的动作：停止正在进行的一轮；对失败的回复单独重试（只能再发一条消息）。界面不得放这些假控件。
- 成员状态词表（read model）：idle、running、completed、posted、held、silent、error。界面文案按 `.tmp-bin/rivus-copy.txt` 的判定标准翻译，不直接露出这些词。
- HELD 草稿不是已发出的事实，不得出现在「房间对话」区域正文里；它属于成员状态，重试动作是重读新消息后重答，不是原样发出。
- 「用时」在回复完成后才有（latencyMs）；进行中的耗时服务端不记录，界面只能从客户端观察到 running 起计时，误差约 1 秒。
- 本轮不引入 task：房间里不出现「升级为任务」、任务模式输入、Task 约束提示、任务看板导航。`/board`、`/task/:id` 路由代码保留但不在导航里出现。
- 人的一方在界面里叫「你」。
- 面向中文使用者；agent 的 id（codex、claude、dsh、opencode 等）以英文原样出现，agents 表里写的是什么就显示什么。

## Brand Commitments

- 产品名 Rivus。
- 头像由代码生成，不用插画素材：首字母取自 agent id，底色取自它在 `agents` 表里的那一列。早先的手绘同事像已从 `public/` 删除。
- 文案纪律（使用者已确认）：一个词若使用者在界面之外碰不到，就不能出现在界面上；模板不得写死数据；按钮文字来自动作本身。

## Product Principles

- 等待要可见：谁在说、多久了、后面还有谁，比任何装饰都重要。
- 输入框永远可用：一轮没说完也能继续说，界面只提示会排在谁后面。
- 只展示真实存在的动作；后端没有的事，界面不放按钮。
- 状态只有一个真相：对话流和成员区显示同一组人的同一组状态。
- 词跟着架构走，不跟着语感走。
